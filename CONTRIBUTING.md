# Contributing

1. Open an issue describing the user or control problem.
2. Keep fixtures synthetic and preserve the claim boundary.
3. Add tests for decision authority, metrics or data contracts affected by the change.
4. Run `npm run backtest`, `npm run validate:backtest` and `npm run check`.
5. Explain operational and customer-harm consequences in the pull request.

Never weaken exact-payload approval, silently substitute missing features, or present simulated results as production outcomes.
